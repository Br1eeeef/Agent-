# Agent记忆数据库范围与接口设计

## 1 使用场景

系统定位为“学习助理 Agent 的本地记忆组件”。演示用户是一名大学生，Agent 保存以下信息：

- 用户画像：专业、偏好学习时段、常用学习方式。
- 学习计划：复习科目、截止日期、任务优先级。
- 历史问答：最近提出的问题和已经给出的建议。
- 事件记忆：考试、作业、课程安排和完成状态。

系统不实现大模型。GUI中的模拟 Agent 接收用户输入后调用记忆 API，显示召回结果，并可把本次输入保存为新记忆。

## 2 参数设计

| 参数 | 默认值 | 设计理由 |
| --- | ---: | --- |
| 短期记忆容量 N | 20 | 足够演示最近多轮交互，同时容易触发淘汰 |
| LRU活跃索引容量 | 50 | 覆盖常用长期记忆，便于展示访问顺序变化 |
| Top K | 10 | 按最小堆模块的默认值，可设置为1至20 |
| 相关度权重 | 0.5 | 当前问题匹配度应占主导 |
| 重要度权重 | 0.3 | 用户标记的重要事项应得到提升 |
| 新鲜度权重 | 0.2 | 新记忆优先，但不能覆盖相关性 |
| 重要度范围 | 1至5 | 输入直观，归一化方式明确 |

推荐召回公式：

`score = 0.5 * relevance + 0.3 * importance + 0.2 * recency`

其中 `importance=(level-1)/4`，`recency=exp(-ageDays/30)`；相关度可先采用分词后的 Jaccard 相似度。三项均限制在 0 至 1。

## 3 GUI设计

界面使用 Qt Widgets 实现（`agent_memory_gui` 目标），左侧固定导航 + 右侧内容区，
共五个页面。界面不接入大模型，记忆、实体与关系全部由用户手动录入。

### 3.2 页面

**1 总览**：四张 KPI 卡（长期记忆总数、短期队列 `m/20`、LRU `n/50`、实体/关系）；
“最近录入”迷你列表可点击跳转记忆管理；短期队列 20 格占用条，写满后转为橙色并提示
“已开始淘汰最旧记忆”；底部为类型分布环形图与重要度 1–5 柱状图。空库时整页切换为引导态。

**2 记忆管理**：工具条含即时搜索（ID/内容/关键词）、类型筛选、重要度区间、排序
（创建时间/重要度/最近访问/ID）与新增、高级录入、编辑、删除、保存、刷新。
表格列：ID、内容摘要、类型 Chip、重要度点条、关键词、创建时间、最近访问。
右侧详情抽屉显示完整内容、关键词、三个时间戳、是否仍在短期队列、LRU 位置与该记忆的图引用。
新增/编辑对话框提交前做非空、重复 ID、重要度校验，异常以内联错误条呈现。

**3 智能检索**：左侧参数卡（查询、K 值 1–20、三项权重滑块，实时显示“滑块值 → 实际权重”，
权重和必须为正）；结果区为卡片列表，每张卡展示排名、ID、内容、类型、总分与
相关度/重要度/新鲜度三条 mini bar；底部 Qt Charts 堆叠水平柱状图展示 Top-5 的得分构成。
点击结果卡会调用 `MemoryManager::find` 刷新 LRU，LRU 面板顶部同步显示“最近读取：<ID>”。
该操作刻意不弹全局提示：读记忆是高频动作，每点一次就弹一次提示会刷屏。

**4 实体关系**：三栏布局。左栏为实体列表（搜索、类型筛选、是否含失效项）；
中栏为 `QGraphicsView` 自绘力导向图，节点为类型色圆角矩形，边带箭头与关系文字，
线宽随 confidence 变化、失效边为灰色虚线；支持滚轮缩放、拖拽节点、单击高亮一跳邻域、
双击查看详情、右键编辑/设为失效/合并占位实体/发起 BFS 或 DFS，右上角有图例浮层，
节点超过 150 个时自动降级为只显示选中实体的一跳邻域。

图谱布局分三步，目的是打开即可读、不需要手动把节点拉开：

1. 力导向迭代，理想间距按节点的实际尺寸计算，长标签的节点不会互相压住；
2. 矩形去重叠松弛，按穿透较浅的轴把相交的节点分开；
3. 节点避开连线，防止某条边被第三个节点挡住而看起来断成两截。

节点填充始终不透明（淡化用颜色与底色混合实现，而不是降低图元透明度，否则连线会从节点
下方透出来）；关系文字会自动沿法线避开其他节点矩形，保证边上的字看得见。
右栏为检视面板：实体详情（含证据记忆链接）、关系表（支持修改关系与逻辑删除，
旧边以删除线保留在历史中）、BFS/DFS 面板（BFS 出邻域表，DFS 输出完整推理链）。

**5 系统状态**：四张状态卡（短期队列、LRU、哈希表、数据文件）；中部左侧为 20 格环形队列
示意（标注队列头/尾，已删除的残留 ID 打叉），右侧为 LRU 顺序列表并带“访问”按钮现场演示；
底部为操作日志表（时间、操作、对象、结果、耗时、说明，失败为红色行），
支持按操作过滤、只看失败、复制与清空；最下方为危险操作卡（清空数据、重新播种），
均需二次确认且不会删除磁盘上的 JSON 文件。

**高级录入对话框**（记忆管理页与实体关系页共用）：三个页签依次为记忆、实体草稿、
关系草稿；提交时组装 `RememberRequest` 调用 `GraphMemoryService::remember`，
在一次事务内写入记忆与图谱，并回显新建/合并实体数与占位实体数；
另有“仅写记忆（不入图）”开关等价于 `MemoryManager::add`。
实体页签的“从内容提候选”只是本地字符串启发式，不做任何模型抽取。

### 3.3 与核心库的边界

- GUI 不得保存任何核心对象的裸指针：表格模型只保存 ID 与数据快照，刷新时重新向
  `MemoryManager` / `GraphStore` 取值；所有写操作都经 `AppContext` 转发。
- 界面如实呈现核心的真实语义，不做美化：`remove` 不清理短期队列，因此列表会出现
  “已删除的残留 ID”幽灵行；`recall` 不触碰 LRU，只有 `find` 才会改变访问顺序；
  载入数据后短期队列的顺序取决于存储遍历顺序。
- 示例记忆的时间戳在播种时会整体平移到当前时间，让
  `recency = exp(-ageDays/30)` 在演示中可见；用户自己的 `memories.json` 不受影响。

## 4 验收功能

- 新增、查看、编辑和删除记忆。
- 短期记忆超过20条时自动淘汰最旧记录。
- 通过ID平均O(1)查找长期记忆。
- 读取记忆时更新LRU顺序；超过容量时淘汰最久未访问项。
- 保存到本地JSON并能在重新启动后恢复。
- 拒绝空ID、重复ID、非法重要度和损坏JSON。
- 提供不少于20个核心模块测试断言。
- Qt界面可调用核心API，不需要修改数据结构内部实现。

## 6 最小堆检索设计

评分公式：

`score = 0.5 * relevance + 0.3 * importance + 0.2 * recency`

| 分项 | 计算方式 | 说明 |
| --- | --- | --- |
| relevance | 分词后集合的 Jaccard 相似度 | 查询与记忆之间的相关度 |
| importance | `(level - 1) / 4` | level 为 1 至 5 的重要等级 |
| recency | `exp(-ageDays / 30)` | 随存储时间衰减的新鲜度 |

实现要点：

- `MinHeap` 是通用最小堆模板；`MemoryRetriever` 把“更差者更小”作为比较器，
  堆顶即当前最差候选，超过 K 时弹出，整体复杂度 O(n log k)。
- 分词与相关度分别抽象为 `Tokenizer` / `RelevanceStrategy` 接口，
  默认实现为 `SimpleTokenizer`（ASCII 按词、CJK 单字加二元组）与 `JaccardRelevance`，
  可替换为词典分词、BM25 或向量余弦而不影响其他模块。
- 记忆在录入（`MemoryManager::add` / `update`）时完成分词并写入 `keywords`，
  查询时直接复用，避免重复计算。
- `MemoryManager::recall(input, k, weights)` 返回带 `score/relevance/importance/recency` 的结果。

## 7 图数据库设计

数据模型：

- `Entity`：概念、客观事实、用户偏好三类（外加 `Other`）。节点记录名称、别名、描述、
  来源 `sourceMemoryId`、证据 `memoryIds`、创建/更新时间、`active` 状态与失效信息。
- `Edge`：`from`/`to`、`relation`、`description`、`eventTime`、`validFrom`/`validTo`、
  `memoryIds`、`source`、`confidence`、`priority` 以及失效信息。
- memory 不作为图节点，只通过 `memoryIds` 作为证据关联到实体与关系。

关键行为：

- **逻辑删除**：实体与边都不物理删除，失效时置 `active=false` 并记录
  `invalidAt` / `invalidReason`。
- **实体消解**：`GraphStore::resolveEntity` 与 `addEntity` 按名称归一化、别名、
  名称相似度合并；类型明确不同时不合并。
- **占位实体**：关系指向未知实体时创建占位节点，后续可通过
  `GraphMemoryService::resolvePlaceholder` 合并到真实实体。
- **边去重**：`from`/`to`/`relation` 完全相同的边合并 `memoryIds`，不重复建边。
- **修改关系**：`updateEdge` 失效旧边（`invalidReason=superseded`）并新增新边，保留历史。
- **事务**：`GraphTransaction` 基于快照，析构时未提交则回滚；
  `upsertEntityWithRelations` 与 `GraphMemoryService::remember` 全程在一个事务内完成。

检索与遍历：

- `EntityQuery` 支持按 id、类型、名称、别名、`memoryId`、时间、`active` 与模糊检索。
- `EdgeQuery` 支持按 from/to、方向、relation、时间、`active`、来源与证据 memory 检索。
- `bfs` 支持指定层数与返回项数，按时间近因、来源可信度、实体类型、关键词匹配打分排序。
- `dfs` 返回完整路径（含经过的边与关系），便于解释推理链与因果链。

长期记忆流程：

- 写入：`RememberRequest`（memory + 实体草稿 + 关系草稿）→ 实体消解 → 建边 → 关联 memory_id。
- 检索：`GraphMemoryService::recall` 识别实体 → BFS/DFS 扩展 → 过滤无效/过期 → 排序 → 返回
  实体、关系与证据 memory。
- 更新与冲突：`reviseEdge` 失效旧边、新增新边，不覆盖旧事实。
- 遗忘：`forgetEntity` / `forgetEdge` 逻辑删除并连带失效相关边，保留摘要与历史。

## 8 新增验收功能

- 最小堆 Top-K 召回默认 K=10，结果按 score 降序且包含分项得分。
- 分词与相关度策略可替换，记忆录入时完成分词。
- 实体与边的增删改查、按多条件检索、实体消解与占位实体合并。
- 边去重合并证据、修改关系保留历史、实体与边逻辑删除。
- 事务化写入失败时整体回滚，不留下半成品数据。
- BFS/DFS 遍历，DFS 返回完整路径。
- 实体关系图的 JSON 保存与重新加载。
- 核心模块测试断言累计 198 条。
