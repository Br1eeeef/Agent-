# Agent记忆数据库范围与接口设计

## 1 使用场景

系统定位为“学习助理 Agent 的本地记忆组件”。演示用户是一名大学生，Agent 保存以下信息：

- 用户画像：专业、偏好学习时段、常用学习方式。
- 学习计划：复习科目、截止日期、任务优先级。
- 历史问答：最近提出的问题和已经给出的建议。
- 事件记忆：考试、作业、课程安排和完成状态。

系统不实现大模型。GUI中的模拟 Agent 接收用户输入后调用记忆 API，显示召回结果，并可把本次输入保存为新记忆。

## 2 参数设计

| 参数 | 默认值 | 设计理由 |
| --- | ---: | --- |
| 短期记忆容量 N | 20 | 足够演示最近多轮交互，同时容易触发淘汰 |
| LRU活跃索引容量 | 50 | 覆盖常用长期记忆，便于展示访问顺序变化 |
| Top K | 5 | 结果数量适合GUI浏览，可设置为1至20 |
| 相关度权重 | 0.5 | 当前问题匹配度应占主导 |
| 重要度权重 | 0.3 | 用户标记的重要事项应得到提升 |
| 新鲜度权重 | 0.2 | 新记忆优先，但不能覆盖相关性 |
| 重要度范围 | 1至5 | 输入直观，归一化方式明确 |

推荐召回公式：

`score = 0.5 * relevance + 0.3 * importance + 0.2 * recency`

其中 `importance=(level-1)/4`，`recency=exp(-ageDays/30)`；相关度可先采用分词后的 Jaccard 相似度。三项均限制在 0 至 1。

## 3 GUI设计

GUI建议使用 Qt Widgets，采用左侧导航和右侧内容区。

1. 总览页：显示短期记忆数量、长期记忆数量、LRU容量、最近保存时间和最近操作。
2. 记忆管理页：表格展示ID、摘要、类型、重要度、创建时间；支持新增、编辑、删除、搜索和手动保存。
3. 智能检索页：输入问题、设置K值和三项权重；展示召回记忆及分项得分。
4. 实体关系页：展示实体列表、邻接关系及BFS/DFS结果。
5. 系统状态页：显示循环队列头尾、哈希桶负载、LRU顺序、数据文件路径和错误日志。

GUI不得直接保存裸指针。所有操作通过 `MemoryManager` 或后续 `MemoryService` 完成。

## 4 验收功能

- 新增、查看、编辑和删除记忆。
- 短期记忆超过20条时自动淘汰最旧记录。
- 通过ID平均O(1)查找长期记忆。
- 读取记忆时更新LRU顺序；超过容量时淘汰最久未访问项。
- 保存到本地JSON并能在重新启动后恢复。
- 拒绝空ID、重复ID、非法重要度和损坏JSON。
- 提供不少于20个核心模块测试断言。
- Qt界面可调用核心API，不需要修改数据结构内部实现。
